    How the AI was made¶

    How Printer Buddy's failure-detection models were built, what they can't do yet, and the data and software they're built on. Using the AI is on AI failure detection.

    The first model: basic-v1¶

    • MobileNetV3-Large, 224 x 224 input, ONNX, runs on a CPU (about 7 ms per image on a PC; a Pi 4 is slower but fine for a check every few seconds)
    • Trained on 31,934 images, tested on 2,907 held-out images
    • Default alert threshold 0.6

    Test results (alert labels, per frame, before the "hold for several checks" rule):

    Threshold Failures caught Correct when it alarms False alarms on frames without an alert problem
    0.5 92.2% 95.7% 4.0%
    0.6 91.5% 96.2% 3.5%
    0.7 90.6% 96.5% 3.2%
    0.8 89.3% 97.0% 2.6%

    Newer model releases list their own test scores in the release notes under Model check. All models: releases tagged ai-.

    Limits¶

    • The test images come from the same kinds of sources as the training images. On your own printers, cameras and lighting it will do worse than the table above. Tell us about misses and false alarms.
    • first_layer looks perfect in testing but most of its images come from one dataset, so it may be recognising that camera rather than the defect. Don't trust it yet.
    • failure is a vague label from datasets that only said "fail"; it scores poorly on its own. Real failures are usually caught by spaghetti or warping anyway.
    • Clean "OK" prints are only about 11% of the data, so false alarms are the main thing we're working on.

    How it was made¶

    1. Twelve public datasets were downloaded, their labels mapped onto ours, and duplicates removed (4,766 copies) to make one dataset: 34,841 images.
    2. Every image was resized (max 640 px) and given image-level labels. Box sets: any box = that label. Folder sets: the folder name is the label. Images with no problem are "OK".
    3. A MobileNetV3-Large (starting from ImageNet weights) was trained for 30 epochs in Google Colab; the best epoch (24) was kept and exported to ONNX.

    Ideas¶

    • PrintGuard by Oliver Bravery (GPL-2.0) - showed that a small, fast model on a Pi works, and the "hold for a while before acting" alert idea. Its list of datasets pointed us to several of the sets above. No PrintGuard code or model is used.
